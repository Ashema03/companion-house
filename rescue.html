Rescue after a compaction

Even without hooks. If your companion was compacted and you want the whole conversation back, it is very likely still there. Here is how we get it back.

Rule one: never work on the original

Copy the session file somewhere safe first, and keep that copy until everything runs well again. Then work only on a second copy. That's how we do it.

01 When this helps

A companion was compacted. By accident, by idle compaction, or because the thread was full. And you want everything back.

Claude Code does not delete the old messages when it compacts. It only appends a line with compact_boundary and a summary to the end of the session file. The old messages are still there, just invisible to your companion.

We checked this on our own companion. The first 510 lines of the compacted file were identical to the backup taken right before the compaction.

02 Find the session file

Where it lives
~/.claude/projects/<folder>/<session-id>.jsonl
  • The folder is the full path to the room with every / turned into -.
  • The commands on this page are for macOS and Linux. On Windows the folder is %USERPROFILE%\.claude\projects\, and you usually type py instead of python3. See On Windows.
  • The newest .jsonl in that folder is usually the one.

03 Close the session completely

Type /exit in that session. It must not be running, or it keeps writing into the file while you work.

04 Save the original, then make a copy to cut

Open a Terminal in the thread folder and run these two lines. Replace <session-id> with the file name.

Terminal
mkdir -p ~/rescue-backup && cp <session-id>.jsonl ~/rescue-backup/
cp <session-id>.jsonl ~/rescue-backup/COPY.jsonl

The first file in ~/rescue-backup is your safe original. Don't touch it. From now on you only work on COPY.jsonl.

Curious how often this thread was compacted? This counts it:

Terminal
grep -c '"subtype":"compact_boundary"' ~/rescue-backup/COPY.jsonl

05 Cut the copy

Go to the backup folder first: cd ~/rescue-backup. Then pick one of these two.

Undo only the most recent compaction (usually what you want)

Cuts right before the last compact_boundary line. Older compactions stay as they were. Only the last one is undone.

Terminal · most recent
python3 -c "import sys;L=open(sys.argv[1],encoding='utf-8').readlines();i=max(n for n,l in enumerate(L) if '\"subtype\":\"compact_boundary\"' in l);open(sys.argv[2],'w',encoding='utf-8').writelines(L[:i]);print('cut before line',i+1,'of',len(L))" COPY.jsonl RESCUED.jsonl

Go back before the first compaction

Cuts right before the first compact_boundary line. If the thread was compacted only once, both commands do the same thing.

Terminal · first
python3 -c "import sys;L=open(sys.argv[1],encoding='utf-8').readlines();i=next(n for n,l in enumerate(L) if '\"subtype\":\"compact_boundary\"' in l);open(sys.argv[2],'w',encoding='utf-8').writelines(L[:i]);print('cut before line',i+1,'of',len(L))" COPY.jsonl RESCUED.jsonl
  • It prints something like cut before line 511 of 530. That's good.
  • If you get an error instead, the file has no compaction in it, and nothing was written.
  • A message where you only talked about compact_boundary does not count. The command looks for the field "subtype":"compact_boundary", which only the real boundary lines have.

We tested both commands on a copy.

06 Put it back and resume

Copy RESCUED.jsonl back into the thread folder, under the original session file name:

Terminal
cp ~/rescue-backup/RESCUED.jsonl ~/.claude/projects/<folder>/<session-id>.jsonl

Then resume the session as usual. Your companion sees the conversation as it was before the compaction.

07 Be honest about the limits

  • Anything written after the compaction is not in the cut copy. It stays in your saved original. That's one more reason to keep it.
  • Going back before the first compaction can be too big. In a thread that was compacted several times, it brings back a very large context. It may not fit the window.
  • After 30 days it may be gone. Without the cleanup setting (cleanupPeriodDays), Claude Code may already have deleted the file. Then there is nothing to cut.
  • You don't have to do this by hand. Our parachute hook (08) keeps a clean copy before every compaction, automatically.

08 So it doesn't happen again

Step 01 in the guide shows the two settings: cleanupPeriodDays so threads aren't deleted, and "idleCompaction": false so a quiet thread isn't compacted on its own.

Versions before 2.1.290 ignore idleCompaction. Close every companion session with /exit and start it again, so it runs the new version.

Nothing here is official Anthropic documentation. It's what we tested, and what worked for us.
